# Content Pipeline Skill

## Goal
One media asset (image or video) gets analyzed by Gemini exactly once, producing a single Master Content JSON object. Every platform-specific post is then generated by deterministic local template substitution against that one object — never by a separate AI call per platform. This keeps AI usage low, keeps brand voice consistent across platforms, and makes adding a new platform later a templating problem, not an AI-prompting problem.

## Master JSON Contract
Every Gemini analysis call must return exactly this shape, and nothing else:

```json
{
  "product": "string",
  "headline": "string",
  "description": "string",
  "keywords": ["string", "..."],
  "hashtags": ["#string", "..."],
  "mood": "string (optional, e.g. festive, minimal, premium)",
  "suggested_cta": "string (optional, overrides workspace default CTA)"
}
```

Do not add fields, do not omit required fields, do not wrap the JSON in markdown fences or commentary.

## Gemini Call Rules
- Pass workspace brand context (brand voice, emoji style, default hashtags) into the prompt so headline/description match the client's tone — but the `hashtags` Gemini returns should be content-specific, not the workspace's default hashtags. Default hashtags get appended at the template layer, not generated twice.
- For images: send inline (base64) for the vision call.
- For video: use Gemini's native video understanding. Inline works for small clips; anything large enough to risk hitting payload limits should go through the File API upload path rather than inline base64 — don't silently truncate or skip frames.
- The system/instruction prompt must explicitly state: "Return ONLY valid JSON matching this exact schema. No markdown, no preamble, no explanation."
- Wrap every call in try/catch. If the response isn't valid JSON, attempt exactly one repair re-prompt ("the previous response was not valid JSON, return only the corrected JSON"). If that also fails, set `Media.status = FAILED`, store the raw response for debugging, and stop — do not retry indefinitely.
- Ingestion (watch-folder or upload) must never block on this call. A new file creates the `Media` row synchronously with `status = NEW`; the Gemini analysis runs as a separate async job that moves status through `ANALYZING` → `ANALYZED` / `FAILED`.

## Template Rendering Rules
- One `Template` row per workspace+platform, with placeholders like `{{headline}}`, `{{description}}`, `{{hashtags}}`, `{{cta}}`. Fall back to a global default template if a workspace hasn't customized one for that platform.
- The renderer is pure string substitution. It must never call Gemini. If a template references a field the Master JSON doesn't have, leave it blank — don't trigger a new AI call to fill the gap.
- After substitution, always append the workspace's `defaultHashtags` after the AI-generated hashtags (deduplicated), then enforce per-platform limits:
  - LinkedIn: body ≈3000 char max, ~5 hashtags max
  - Pinterest: title ≤100 chars, description ≤500 chars
  - YouTube: title ≤100 chars, description ≤5000 chars
- A media asset that is `IMAGE` type can only render LinkedIn and Pinterest posts. YouTube requires `VIDEO` type — never silently generate a YouTube draft from an image-only asset (see the platform-publishing skill for the enforcement point).

## Validation
Run the platform-constraint check immediately after rendering and before a post is allowed to move into a schedulable state. Surface violations in the UI (e.g. "description 40 chars over Pinterest limit") rather than silently truncating without telling the user.
